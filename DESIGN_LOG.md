# flowkit design log: every UI and logic decision, and why

This is the memory of the project. Read it before changing anything. Entries say **what**, **why**, and what was **rejected**.
Origin: the CIVL909 pile "block display" (`interface_playbook/`), rebuilt twice: first as a Grasshopper-style flow map (`interface_playbook/flowmap/`), then generalised into this kit with two tracks (shallow, deep).

## 0. First principles (the brief, in the user's words, condensed)
- Create an **abstraction function**: an equation, a lookup chart or table, anything that needs computing. It is **fed inputs** and **returns an output**; that output feeds the next function. Sometimes a **decision gate** alters values or functions.
- Any function can be **expanded to peek inside**. **Nothing hidden unless asked.** The **whole picture is always there**; **zoom, drag and good navigation are a must**.
- The result is a **flow map** of every element of the problem and how it affects the final result, directly and indirectly.
- Study jobs: work a problem, look up a symbol, check a concept, find a problem by week/type/source. One interface, two foundation tracks, reusable for any subject.

## 1. Rejected from the old interface (and why)
| Old | Why it failed the brief |
|---|---|
| One focus at a time: stages → a stage → a step (semantic zoom replaced the canvas) | hides how things affect the result; you never see the whole picture |
| Noun / adjective / verb grammar, "a verb makes exactly one noun", Lines vs Wires views | forced every computation into "verb"; no multi-input functions as one idea; Lines was a form, not a map |
| Tap-to-open, prev/next only; no pan/zoom/drag | navigation was missing |
| Side inspector that shrank the canvas | the canvas jumped when you clicked |
| Per-problem generated layouts that wrapped back leftwards | wires ran backwards; unstable pictures |

## 2. The model (kit/core/decl.js, kit/ui/flowmap.js buildModel)
- **Blocks**: *input* (given, purple halo), *const* (fixed by a rule, dashed), *function*, *gate* (decision), and **every function and gate is followed by its own RESULT block** ("always output a value block after a function"). Groups (stage/step) are **frames only**, never blocks.
- A function is `Fn(id,'expression',…)`. **Wires come from the identifiers in the expression**: nothing is wired by hand, so the picture cannot disagree with the maths. A gate used in an expression draws a dashed *qualifier* wire.
- The canvas consumes a **program** `{nodes, edges, steps, stages, stageOf, verify}`. Two producers: the declarative compiler (kit) and **adapters** (a subject's own engine; CIVL909's pile engine). The canvas knows nothing else.
- Leaf blocks are `F:<verb id>` (function), `G:<id>` (gate), `I:` (input), `C:` (const). Result blocks are not leaves: they belong to their function and are drawn beside it.
- **Verification**: each problem may carry `check`; the top bar shows `✓ matches the official …` or `≠ differs from … (here …)` with a note. Never hide a mismatch (exam Q4 shows one on purpose).
- **Rejected**: a block per noun *and* per verb as separate wired items (doubled the graph; the function+result pair is enough); collapsing groups into aggregated boxes with aggregated ports (see 3).

## 3. Groups are Grasshopper "Groups", not "Clusters"
Stage and step are **coloured frames drawn around their members**: they hide nothing, own no pins, wires pass straight through, the frame **resizes to its members** as you drag them, dragging the frame title moves all members. Nested (stage ⊃ step). A toggle shows/hides frames.
Rejected: collapsible boxes (+/− with aggregated pins), level buttons "Stages/Steps/Functions", top-down collapsed overview. They violated "nothing hidden".
The navigation job that collapsing tried to do is done by the **Jump** pill (§9) and the minimap.

## 4. Layout (kit/ui/flowmap.js layoutContainer)
- **Layered, left to right**: a block sits one column right of everything that feeds it (longest path, cycle-safe: back edges are ignored). An input with no feeders waits in the column just before its first user.
- **Lanes**: a wire that must cross several columns gets a dummy slot in every column it crosses (one chain per source block and destination block), so it passes *between* blocks, and lanes take part in crossing minimisation (16 barycentre sweeps + 3 balancing sweeps). The wire is drawn through its lane waypoints (`lanePts`, `wireD`): leave the pin to the right, ride the lane, arrive from the left.
- Pin rows on a block are ordered by where their wires come from (fewer crossings at the pins).
- Nested containers: a frame is laid out as its own container (so frames never overlap), then drawn as the bounding box of its members (§3).
- **Never wrap into rows** (an earlier version wrapped long strips; it made wires run backwards). The picture is a long strip; zoom and Jump handle it. All 19 pile + 28 shallow problems: zero backward wires, zero overlapping blocks (checked by script).
- **Tidy** resets manual positions. Manual drags are offsets on top of the layout (`FM.off`), per block and per frame (frames carry their members).
- Option not taken yet: a stronger engine (ELK) for fewer crossings, at a large file-size cost.

## 5. Navigation (React Flow "design tool" model, no library)
- Pan is the default drag on empty canvas (slippy map); **Shift-drag box-selects** (or switch the tool with V / H; the Pan/Select button). Space-drag, middle and right drag always pan.
- Wheel: **Ctrl/Cmd+wheel and pinch zoom**; a **mouse wheel** (large integer steps) zooms and eases (170 ms); a **trackpad two-finger scroll pans**; Shift+wheel pans sideways. Zoom is anchored on the cursor, range 5 %–400 %.
- Release a fast pan and it **glides**. Double-click a block zooms to it; double-click empty canvas zooms in (Shift: out).
- Keys: `F`/`Home` fit · `Z` zoom to selection (or fit) · `0` 100 % · `+ -` zoom · arrows pan · `[ ]` previous/next step · `V H` tools · `W` wiring · `Ctrl+Z` undo · `Ctrl+A` select all · `Esc` clear/close · `Ctrl+K` or `/` lookup.
- **Multi-select**: box-select, Shift/Ctrl-click; dragging any selected block moves all; the side panel then lists them with a switch-off button. Selection **lights the whole chain**: blue = everything that feeds it, orange = everything it feeds (direct and indirect). Hover lights only a block's own wires.
- **Minimap** (drag along it), zoom buttons, **Fit**, **Zoom to selection**, search ("Find a block…").
- The canvas side panel floats over the canvas (never resizes it) and shows only groups and multi-selections; single blocks open the dialog (section 7); the companion has the right-hand column (7b).

## 6. Wiring: plug / unplug / switch off (switchable)
- **Wiring** button (W) turns the mechanism on/off. On: click a wire to unplug; drag a result block's pin to a pin to plug; drag off an input pin to pick a wire up; click a red ghost wire to restore. Each function and gate has a ⏻ switch-off button. **Undo** (Ctrl+Z), **Plug everything back**.
- Semantics: an unplugged wire or a switched-off function gives **no result**, and "no result" propagates downstream (red dashed blocks, result `—`), like null data in Grasshopper. The top bar counts what is cut.
- **Limit (honest)**: for adapter problems the numbers come from one engine, so unplugging cuts the *dependency*, not the arithmetic, and a pin only accepts its original source. Declarative problems are executable, so true re-wiring to a different compatible source is possible later (not built).

## 7. Inspection: a pop-up dialog (revised)
The first version was a floating card in the middle of the canvas. It was rejected: the canvas swallowed the mouse wheel so the card **could not scroll**, and its gradient hero equation, thick coloured borders and glow looked **cartoonish**.
- Now a real **dialog**: fixed overlay with a light backdrop, a header (small flat logo, kind, name, ×), a **scrolling body** (the wheel scrolls it; the canvas never sees it), a footer (switch off, Close). Esc, ×, Close or a click on the backdrop closes it. One at a time. Flat, hairline-separated sections, small-caps labels, one restrained serif for maths.
- Section order: practice prompt (if on) → **Equation** (a quiet block with an accent bar: symbolic, numbers put in, result with its dimension) → what it takes → **How it was found** (the chart, click to zoom; the steps) → notation → what it feeds. Inputs: value, "Use my own value", and **Effect on the answer** ("+10 % of this input moves the answer by …", or "does not change the answer: a distractor").
- Chart look-ups always show their chart; click it for the zoom lightbox (z-index above the dialog).
- Rejected: floating card anchored to the block; auto-panning the canvas to keep the block visible (the dialog is modal, so no need).

## 7b. The companion (kit/ui/companion.js, scene.js): learned from the old pile explorer
What the old explorer had that a flow map alone does not: the question as set and **what it asks**, **what is given but not needed**, **check your answer** (±3 %) and hide-the-solution practice, a **worked solution that reads like a textbook** (given, goal, numbered steps with the concept, equations, numbers, running results) that **drives the other views** ("follow while reading"), **physical drawings**, and **conventions and flags**. First principle: the map shows how things relate; the student also needs what was asked, what it looks like, the working in order, why, what to watch for, and a way to test themselves.
A right-hand column (open/closed with **Companion**, remembered; an overlay on narrow screens) with four tabs:
- **Question**: week/type/source chips, the question text, **What it asks**, **Given**, **Given, but not needed** (inputs with no path to the answer, found automatically), **Fixed or read from charts**, **Check your answer** with Reveal, and the **Practice** switch.
- **Picture**: the physical situation drawn from the problem's own numbers (it redraws when you edit an input). Kinds: footing, stack (layers, water table, drainage), plan (signed rectangles), cpt, spt, chart. Declared with `Scene(id,{...})`, apart from the numbers.
- **Solution**: the working written out step by step, generated from the program: Given, Goal, each step (title, the *why* from `Notes`, then every function with its equation, numbers, result, chart and "How it was found"), Answer with the official comparison. **Follow while reading**: scrolling or clicking a step lights that step's blocks on the map and fits its frame; clicking a line selects its block.
- **Notes**: the idea, what to watch for, conventions and flags (from `Notes`, check notes, and givens that say "official/assumed"), **Symbols in this problem** (notation table with Look up), more problems of the same type.
**Practice mode**: every function and decision result is hidden (`?`) until you check it (number within 3 %, or Yes/No for a decision) or reveal it; the dialog gets a "Your answer" box; the top bar says so. **Edited inputs** show "N inputs changed, Back to the question".
Teaching text is **data**, kept apart from the numbers: `Notes(id,{idea, steps:{stepId:'why'}, traps, assumed})`, `Scene(id,{...})`.
Rejected: a separate "Worked example" page (the Solution tab is generated from the same program, so it cannot disagree with the map); locking worked examples (inputs stay editable, with a one-click reset).

## 8. Visual system (logos, colours, type)
- **Functions** are bold gradient tiles with a white 24-px stroke glyph (Lucide rules: 2 px, round joins; Blender idea: the icon says what the operation *accomplishes*). **Bigger than values** (58 px vs 26) with a **stacked edge** ("made of smaller parts"); decisions are circles (50 px), no stacked edge; the goal tile is dark with a gold glyph.
- **Families** (colour + glyph): soil profile (strata) · chart look-up (curve + reading point) · geometry (set square) · equation (f(x), ×, ÷, +) · add/min (Σ, min) · convert/count (⇄, #) · decision (fork). Classification is by the verb name and vtype (`fnKind`); add patterns for a new subject there.
- **Values** are pills: the **colour is the dimension** (length, area, force, stress, settlement, count, factor/ratio, flexibility, stiffness), the chip is the symbol. Purple halo = given in the question; dashed = fixed by a rule; dark = the final result. The **Key** button explains all of it.
- Function **names** sit under the logo (semibold, on a faint backing) and appear from ~40 % zoom; labels never fall below ~11 px on screen and all share one size (stage titles ×1.15).
- **One type scale** (×1.2): 10.5 / 12 / 13 / 15 / 18 / 22 px, as CSS variables `--fs-1…6`. Content on the canvas scales with zoom; labels use `--lab`. Maths (equation hero, notation symbols) uses one serif italic; everything else one sans.
- States: starved (red dashed), off (grey, faded), selected/up/down (outlines), accept (green, while dragging a wire). Dark mode follows the system.
- Rejected: counter-scaling several different text sizes at low zoom (made sizes inconsistent).

## 9. Jump, step navigator (subtle)
A faint pill at the bottom centre: `2/7 Find the shaft resistance… ‹ ›`; it follows the step nearest the middle of the view; click the title for the list of steps grouped by stage; `[` `]` step through. Opacity 55 % until hover. Present, never the focus.

## 10. The shell (kit/ui/shell.js): master tabs and tracks
First-principles jobs → tabs: **Map** (work a problem), **Library** (find a problem), **Notation** (look a symbol up), **Quiz** (check a concept). The **track** (e.g. Shallow | Deep) scopes the problems, the notation and the quiz; flipping it while on the Map opens that track's library. Hash route `#track/tab/problem`; track, tab, group-by, question-open, quiz answers and "opened" ticks persist in localStorage (namespaced by subject id).
- **Library**: facets **by week**, **by type of problem**, **by source** (tutorial / exam / lecture / quiz); search; cards show week, type, source, official answer; exam papers have their own "Exam papers" group; the MCQ set is a card that opens the Quiz tab.
- **Notation tab**: grouped table, filters (how obtained, group), "this track" or "both tracks" (shows a symbol that means different things in each, with a track badge).
- **Micro-lookup (Ctrl+K or /)**: type a symbol or word; results track-first; the card shows meaning, unit, how obtained, track, week, group; **"In this problem"** (chips that jump to the blocks) and **"Used in worked problems"** (declarative problems whose blocks use that symbol). Symbol matching: each comma part, bracket part, and σ′-less form are keys; trailing digits fall back (`Iz3 → Iz`).
- The old floating Question card is gone: the question lives in the companion (7b).
- **#selftest**: compiles every declarative problem, checks each against its official value, lists broken blocks.
- Rejected: one flat list with a track filter chip (the track is a mode of study, not a filter); a separate Exam tab (an exam is a *source* of problems, not a place); a left sidebar library (steals the canvas).

## 11. Build system
`build.py --subject subjects/x` concatenates, in order: subject JSON consts → `kit/core/*.js` → the subject's `scripts` (adapters first, then `problems/**/*.js`) → `kit/ui/flowmap.js` → `kit/ui/shell.js` into one HTML. **One global scope**: no module system, so names must not collide (SCHEMA.md lists what the kit owns). The kit needs no subject knowledge; a subject needs no kit edits.

## 13. Gotchas learned
- Edit the **source** (`kit/…`, `subjects/…`), never `dist/`. After editing: `python build.py --subject …`; the browser may cache `dist/*.html`: reload with `?v=N`.
- Mid-line `//` comments inserted into minified-style one-line functions comment out the rest of the line: use `/* */`.
- Hidden tabs have no size: the canvas fits only when the Map tab is shown (`fmShown`), never while hidden.
- Pointer capture needs real pointer ids; synthetic events in tests need `elementFromPoint`-style checks, not `setPointerCapture`.
- Screenshots of an emulated narrow viewport are scaled down: test visuals at the real pane size.
- Python heredocs with many quotes break in the shell: write patch scripts with the file tools.

(exam | tutorial | lecture | external), `likely` (1 to 3), `symbols[]` (notation keys, shown as chips that open the Ctrl+K lookup) and `link` (a Map problem).
The Quiz tab filters by week, kind, source, pattern and "likely on the final", groups by week, pattern or source, and has a collapsible *Final exam prediction*
panel (a bar per pattern, the questions in it, your score) with a per-track note. `quiz/_make_bank.py` generates the files: calculation answers are computed there, never typed.
(b) `subjects/civl909/VERIFICATION.md` records an independent recomputation of every worked answer. (c) A third track **walls** (weeks 11 and 12) with its own
types, notation group "Retaining walls", problems (`problems/walls/`), notes and a 30-item bank.
**Why.** The user asked for correct worked solutions (so the audit is part of the product), about 100 multiple-choice questions systemised by week, pattern and
source and linked to the notation, a prediction of the final, and the two new weeks. A track is the existing scoping mechanism, so no kit change was needed for walls.

## 15. Portable inspector and the exam generator
**Inspector.** `#mod` is now a layer with no backdrop and `pointer-events:none`; `#modwin` is absolutely positioned, draggable by its header, resizable from the corner, its position is remembered (`localStorage modpos`, clamped to the viewport), and it stays open while you pan, zoom and click other blocks (clicking another block swaps its content; Esc or × closes). Clicking empty canvas and Jump no longer close it. *Rejected:* a backdrop or blur (the user wants to keep working on the map); closing on any canvas click (defeats "portable").
**Exam tab (kit: `core/exam.js`, `ui/exam.js`; subject: `exam/blueprint.json`, `exam/templates.js`).** A paper has sections of *slots*. A multiple-choice slot draws `n` questions from the banks by pattern (flagged items excluded, options shuffled, no repeats). A numerical slot draws one *template* from a pool; a template (`ExamQ`) names a declarative problem, draws its inputs (`p`: lists or ranges; `derive`: dependent inputs such as α from c_u; `ok`: reject unusable draws) and the answer is **computed by the same expressions as the worked solution**, so key and Map always agree. A version is a seed plus a swap counter per slot; the code `SEED-0.0.1.…` rebuilds the same paper, "Swap" re-draws one slot only (each slot has its own random stream), "New version" re-draws everything. Answer key toggle, print stylesheet, and "Worked solution on the map" opens the problem with that version's numbers. 26 templates, 10 + 7 slots, about 78 marks.
**Rules for templates.** Chart look-ups only hold at the points stored (φ is drawn from 30, 35, 40; C_N within 29 to 87 kPa); inputs that feed typed readings (the W5 Q3 I_z values) are not drawn; every draw is stress-tested (`xnum` over 150 seeds per template, no nulls, no non-finite answers) and a sample was recomputed independently in Python.
**Also added.** Five declarative pile problems from the week 7 to 9 lecture examples (`problems/deep/d_lecture.js`) so the deep track has computed numerical templates (the old pile engine's problems cannot take drawn inputs).

## 16. Quiz tab redesign (kit/ui/quiz.js)
**Why.** The first bank view put every filter, a sort, the prediction table and 100+ cards on one page: no regard for how a person studies. **Precedent read:** UX StackExchange 62405 (one question per screen when instant feedback helps; always show progress; keep transitions client-side), Quizlet's 2021 study-mode redesign (no sidebar, the same question interaction everywhere, feedback shown in place, emphasise the correct answer rather than the wrong one), and the HackerRank / Edulace exam pages (question grid to jump, practice vs exam mode, flag for review, progress bar, keyboard access, text size).
**What.** *Focus view* (default): one question, a grid of numbers (coloured: answered, right, wrong, flagged, current) that scrolls and turns into a strip on narrow screens, big readable text, options full width. *List view* kept for skimming. *Practice mode*: feedback at once, "Try again". *Test mode*: answers stay quiet, can be changed, "Finish" reveals score and a weakest-topic-first breakdown, "Review the wrong ones", "Retake". Filters (week, kind, source, status unanswered/wrong/flagged, topic, likely) live behind one "Filters · n" button; shuffle; A−/A+ text size; keys 1–4 or A–D, ←/→, F. Preferences (mode, view, size, shuffle, filters) are remembered per browser; the prediction panel is collapsed until asked for.
**Rejected.** Timers and streaks (no exam clock is wanted for study); hiding the grid on desktop (the jump map is the main orientation aid); a sidebar of filters (Quizlet removed theirs).

## 17. Anki export of the notation (anki_export.py)
**What.** `python anki_export.py --subject subjects/civl909` writes `subjects/civl909/anki/CIVL909_notation_reverse.apkg` (needs `pip install genanki`): one **reverse** card per symbol. Front = what it means in the real world (+ the sheet's group as a small context line, to tell apart symbols such as the two δ). Back = the notation (subscripts rendered), then unit, how you get it, track and weeks. Subdecks `<Subject>::<Track>::W<weeks>` (a notation entry carries a week *range*, so the subdeck is the range: W1-5, W7-8, W9-10, W11-12). Tags: track, group, how obtained. GUIDs come from the notation id, so re-importing an updated deck updates cards.
**Decided with the user.** Notation cards only, reverse direction only, extra fields Unit, How you get it, Where; subdecks by track and week; `.apkg`.
**Not included (can be added).** Question-bank cards, formula cards, trap cards.
**Image field (added).** `anki/images.json` (generated by `anki/_make_images_json.py`) maps notation ids to lecture slides (file glob + page + caption); `anki_export.py` renders each slide once to a JPEG (footer trimmed), embeds it in the `.apkg` and puts it on the **back** of the card only (a slide shows the formula, so on the front it would give the answer away). 105 of 184 symbols have one or two slides (54 distinct slides); plain quantities (B, L, z, H, γ …) are skipped on purpose. Slides were chosen by looking at contact sheets of the candidate pages, not by page number alone. *Rejected:* redrawing the charts ourselves (the lecture's own chart is what the exam provides); photographs of the handwritten solutions.
**Logo and Equation fields (added).** *Logo*: the web's own logo system drawn in the card: a **pill** coloured by what the quantity is (length teal, area green, force red, stress blue, settlement purple, angle brown, count amber, ratio grey; from the notation unit, same mapping as `dimOf`) and, when the quantity is produced by a block, the function **tile** that makes it: *f* (equation, blue) for calculated symbols, the set square (geometry, teal) for geometry symbols, the chart icon (orange) for chart readings. Given symbols get the pill only. *Equation*: written only for **geometry** symbols (`anki/equations.json`: effective B′ and L′, areas, shaft and base area, pile weight, overburden, block size, group diameter, area ratio, drainage path, thickness below the base, pressure-diagram areas and centroids). The card then says "f: equation, given on the exam paper" or "geometry: NOT on the paper, learn it": this encodes the user's study rule (equations come with the paper, geometry does not). Where the notation sheet's own meaning already contained the equation, `front` in the same file rewrites the card front so the answer is not shown. *Caveat:* the "equations are given" rule is the user's belief about the paper, not confirmed.

## 18. Anki card layout (anki_export.py, anki/template/)
**Syntax learned** (Anki manual, Templates): `{{Field}}`; `{{#Field}}…{{/Field}}` shows a block only if the field has text (also how an optional card is generated); `{{hint:Field}}` hides a field behind a link; `<hr id=answer>` is where Anki scrolls on "show answer"; card CSS targets `.card` and `.card.nightMode` (older AnkiDroid: `.night_mode .card`); MathJax is written in the FIELDS as `\( inline \)` and `\[ display \]`. Design rules weighed: minimum information on the front, the answer side may carry everything, a hint is a learner's choice not a given, one accent colour, no JavaScript (not supported everywhere), relative font sizes for phones.
**Layout.** *Front*: a small context line (topic · track, so the two OCR or δ cards are not confused), the meaning in plain words, the logo with its symbol hidden "?" echoing the web's value pill, and a "Show Unit" hint link (off by default: the unit narrows the answer, the learner decides). *Back*: the question in small muted type, the divider, the notation large, the web's logo (pill coloured by dimension + the tile of the block that makes it: f, set square or chart), a grey definition strip (back only, so the front never leaks a formula), a teal "Geometry · not on the paper" box with the hidden equations, a quiet unit / comes from / where list, then the lecture slides. Colours: neutral greys, one teal accent; the logo colours are kept only inside the logo. Dark mode through CSS variables. An optional second card (notation → meaning) is generated only for notes whose `Forward` field has text.
**Everything in LaTeX.** Notation, units, definitions, geometry equations, pill symbols and slide captions are MathJax; the symbol converter handles Greek letters, primes, bars, subscripts (words of three or more letters upright), compound subscripts (`Pg,s`, `cu,ave`) and bracketed labels (small). `OCR`, `FS`, `ER` stay upright.
**Paste-in files.** `anki/template/` holds the note type as text: `0_fields.txt` (create the 12 fields in this order), `1_front.html`, `2_back.html`, `3_style.css`, and the optional forward card. *Fields are the same in the .apkg, so importing the .apkg is enough; the files are for editing the template inside Anki (Tools → Manage Note Types → Cards).* Note type id changed, so an old import of this deck should be deleted first.
**Logo on the front (revised).** The front now always shows the web's logo: the pill in its dimension colour with "?" in place of the symbol (the symbol would give the answer away), plus the function tile and its label (f / geometry / chart) when the quantity is produced by a block.
